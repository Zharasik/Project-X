# DESIGN LAB — архитектура

Документ фиксирует анализ требований и принятые решения. Код в репозитории следует этому документу.

---

## 1. Анализ требований

**Главная цель** — студент, пропустивший занятие, за 5 секунд понимает: где он, что сделано, что делать дальше. Отсюда три следствия для архитектуры:

1. **Прогресс вычисляется из реальных действий**, а не из «галочек». Тема завершена, только если:
   - лекция дочитана (кнопка «Я прочитал(а)» в конце лекции);
   - практика сдана (есть `Submission`, не возвращённая на доработку);
   - тест сдан (лучшая попытка ≥ проходного балла);
   - горячие клавиши темы хотя бы раз отвечены верно в тренажёре.
   Кнопка «Завершить тему» лишь проверяет это на сервере и ведёт дальше — сама по себе ничего не засчитывает.
2. **Расписание — отдельная сущность** (`DailyPlan`). «Сегодня», «пропущено», «история» — это запросы к планам группы, пересечённые с прогрессом студента. Курс не знает о датах.
3. **Весь контент — данные.** Курсы, модули, уроки, лекции, тесты, клавиши создаются в Teacher Panel; в UI ничего не захардкожено. Seed-скрипт нужен только для демо.

**Что сознательно НЕ входит в MVP:** оценки по шкале, чат/комментарии, уведомления, drag-and-drop (порядок меняется кнопками ↑/↓), WYSIWYG-редактор (лекции пишутся в Markdown с превью), S3 (локальное хранилище за интерфейсом).

## 2. Структура проекта

```
prisma/
  schema.prisma          — модель данных
  seed.ts                — демо-данные (Web Design: Photoshop + Illustrator)
src/
  app/
    (auth)/login, register          — вход / регистрация по коду группы
    (student)/                      — layout студента (топ-бар + мобильный таб-бар)
      page.tsx                      — Dashboard: Today, пропуски, прогресс, история
      courses/[courseId]            — список тем курса
      lessons/[lessonId]            — обзор темы (шаги 01–04)
        lecture | practice | quiz   — шаги
      hotkeys                       — тренажёр
      quiz/quick                    — быстрый тест
      favorites                     — избранное
    teacher/                        — layout преподавателя (сайдбар)
      page.tsx                      — дашборд: группы, сегодня, очередь проверки
      courses/…                     — CRUD курсов / модулей / уроков
      lessons/[id]/{lecture,practice,quiz,hotkeys}  — отдельные редакторы
      hotkeys                       — библиотека горячих клавиш
      plans/…                       — план занятий
      groups/…, students/[id]       — студенты и их прогресс
      submissions                   — проверка практических работ
      results                       — результаты тестов
    api/files/[...key]              — отдача загруженных файлов (с проверкой доступа)
  components/
    ui/                             — собственные примитивы (Button, Badge, Progress…)
    student/, teacher/              — доменные компоненты
  lib/
    db.ts                           — Prisma client
    auth/                           — сессия (JWT в httpOnly cookie), guards по ролям
    progress.ts                     — ЕДИНСТВЕННОЕ место расчёта прогресса
    schedule.ts                     — today / missed / history
    storage/                        — интерфейс хранилища + local-драйвер
    actions/                        — server actions (student, teacher)
  middleware.ts                     — редиректы по роли
```

**Backend:** Next.js Server Components + Server Actions. Отдельный backend не оправдан: одна БД, одна команда, нет внешних клиентов. Всё обращение к БД — только на сервере; каждое action начинается с `requireStudent()` / `requireTeacher()`.

**shadcn/ui** не подключён: нужные примитивы (кнопка, бейдж, прогресс, поля) написаны вручную в `components/ui` — это ~200 строк и полный контроль над визуальным языком.

## 3. Схема базы данных

```
User ─┬─ StudentProfile ── Group ──┬── GroupCourse ── Course ── Module ── Lesson ─┬─ Lecture
      │                            │                                              ├─ Practice ── Submission ── SubmissionFile
      └─ TeacherProfile ───────────┘ (teacher owns groups & courses)              ├─ Quiz ── Question ── QuestionOption
                                                                                  │         └─ QuizAttempt
                                   DailyPlan ── DailyPlanItem                     ├─ LessonHotkey ── Hotkey ── HotkeyStat
                                   (group + lesson + date)                        └─ LessonProgress
Favorite → (lesson | hotkey) с указанием вида: LESSON / LECTURE / PRACTICE / HOTKEY
```

Ключевые решения:

| Решение | Почему |
|---|---|
| `Role` = `STUDENT \| TEACHER \| ADMIN` | ADMIN зарезервирован, guards уже принимают список ролей |
| Профили отдельно от `User` | данные студента (группа) и преподавателя не смешиваются, User остаётся «учётной записью» |
| `Lecture`, `Practice`, `Quiz` — 1:1 к `Lesson` (`lessonId @unique`) | тема = контейнер шагов; любой шаг опционален, порядок шагов фиксирован |
| `Hotkey` ↔ `Lesson` через `LessonHotkey` (M:N) | одна клавиша (Ctrl+Z) встречается во многих темах — без дублей |
| `Question` + `QuestionOption` | single / multiple / true-false — одна модель; true/false = 2 опции |
| `QuizAttempt.quizId` nullable + `mode` | «Быстрый тест» из случайных вопросов хранится в той же таблице |
| `Submission` уникальна на (practice, student) | одна живая сдача, пересдача обновляет её; статус SUBMITTED → ACCEPTED / NEEDS_REVISION |
| `SubmissionFile` + `storageKey` | загрузка расширяема: сменить драйвер (local → S3) без миграции |
| `LessonProgress` хранит только факты (`lectureReadAt`, `quizBestPercent`, `completedAt`) | статус вычисляется в `lib/progress.ts`; практика берётся из `Submission`, клавиши — из `HotkeyStat` — без дублирования |
| `DailyPlan` (group, lesson, date) + `DailyPlanItem` (тайминг) + `teacherNotes` | студенту отдаются только дата/тема/номер; тайминг и заметки видит лишь преподаватель |
| `published` на Course/Module/Lesson/Hotkey | черновики невидимы студентам |
| `order` на Module/Lesson | явный порядок, меняется ↑/↓ |

## 4. User flows

**Студент, обычный день.** Вход → Dashboard → блок TODAY («Смарт-фильтры», Ps, занятие 4, ~80 мин, шаги Лекция ✓ / Практика ◐ / Тест ○) → одна кнопка «Продолжить» ведёт на первый незавершённый шаг.

**Студент пропустил занятия.** Dashboard показывает «Вы пропустили 2 занятия» (планы группы в прошлом, тема которых не завершена) → «Продолжить курс» ведёт на самую раннюю незавершённую тему.

**Тема.** Обзор (01 Лекция → 02 Практика → 03 Тест → 04 Клавиши), у каждого шага статус. Каждый шаг заканчивается CTA на следующий. «Завершить тему» активна, когда все шаги выполнены, иначе показывает, чего не хватает.

**Тест.** Вопросы по одному → результат (x / n, %), разбор ошибок с правильными ответами → «Пройти ещё раз». Быстрый тест — 5 случайных вопросов из открытых тем.

**Тренажёр.** Выбор категории (Photoshop / Illustrator / Общие / клавиши темы) → показывается действие → студент нажимает сочетание → ✓ / ✗ + правильный ответ → счётчик и процент. Комбинации, которые браузер не отдаёт странице (Ctrl+T, Ctrl+N, Ctrl+W), автоматически предлагаются в режиме выбора из 4 вариантов.

**Преподаватель.** Дашборд: группы (студентов, лекция/практика/тест по сегодняшней теме — 17/18, 14/18, 16/18), очередь работ на проверку, последние результаты тестов. Курс → модули → уроки (создать, ↑/↓, опубликовать). Урок → отдельные вкладки-редакторы: Лекция (Markdown + превью), Практика, Тест (вопросы), Клавиши. План занятий: дата + группа + тема + тайминг.

## 6. Дизайн-система

**Принцип:** типографика и пространство вместо декора. Плотность как в Linear, читаемость статей как в Notion.

- **Шрифты:** Geist Sans (интерфейс, заголовки с отрицательным трекингом), Geist Mono (номера шагов, клавиши, проценты, метаданные).
- **Шкала:** 12 / 13 / 14 / 16 / 20 / 28 / 40. Базовый размер интерфейса — 14px, статьи — 17px.
- **Цвета (CSS-токены, светлая и тёмная тема):**
  - `--bg` нейтральный фон, `--surface` поверхности, `--muted` подложки;
  - `--fg` основной текст, `--fg-2` вторичный, `--fg-3` третичный;
  - `--border` тонкие границы 1px;
  - `--accent` — **один** акцент (индиго), только для главного CTA, текущего шага и прогресса;
  - `--success` / `--warning` / `--danger` — только для статусов и ответов.
- **Поверхности:** радиус 10px (карточки) / 8px (контролы) / 6px (бейджи). Тень — одна, едва заметная, только у всплывающих и главного блока.
- **Статусы:** ○ не начато · ◐ в процессе · ✓ завершено · 🔒 недоступно — нарисованы как 14px SVG, не эмодзи.
- **Программы:** моно-бейджи `Ps` / `Ai` / `⌘` в рамке, без брендовых цветов.
- **Движение:** 150ms ease-out для hover/focus, никаких bounce.
- **Адаптив:** desktop-first; < 768px — нижний таб-бар (Главная, Курс, Клавиши, Избранное), у преподавателя сайдбар сворачивается в горизонтальную навигацию.
