# Design Lab

Образовательная платформа для курса веб-дизайна (Photoshop, Illustrator): лекции, практические задания со сдачей работ, тесты, тренажёр горячих клавиш и план занятий.

Две роли: **студент** видит, что проходили, что делать сегодня и что осталось; **преподаватель** управляет курсами, расписанием и проверяет работы.

Архитектура, схема БД, user flows и дизайн-система описаны в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Стек

Next.js 15 (App Router, Server Actions) · TypeScript · Tailwind CSS 4 · PostgreSQL · Prisma 6 · JWT-сессия в httpOnly cookie (jose + bcrypt).

## Запуск

Нужны Node.js 20+ и PostgreSQL 14+.

```bash
npm install
cp .env.example .env           # заполните DATABASE_URL и SESSION_SECRET (≥ 32 символов)
npx prisma migrate deploy      # создать таблицы
npm run db:seed                # демо-данные (необязательно)
npm run dev                    # http://localhost:3000
```

Демо-аккаунты после `db:seed` (пароль у всех `password123`):

| Роль | Email |
|---|---|
| Преподаватель | `teacher@designlab.local` |
| Студент (пропустил 2 занятия) | `student@designlab.local` |
| Другие студенты группы WEB 2-1 | `student2@designlab.local` … `student18@designlab.local` |

Код группы для регистрации новых студентов: `WEB21-LAB`.

Seed строит расписание относительно сегодняшней даты: сегодня — «Смарт-фильтры», два прошедших занятия демо-студент пропустил. `npm run db:seed` полностью пересоздаёт данные.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения PostgreSQL (на Neon — pooled) |
| `DATABASE_URL_UNPOOLED` | прямое подключение для миграций; локально — тот же URL |
| `SESSION_SECRET` | ключ подписи сессий, ≥ 32 символов (`openssl rand -base64 32`) |
| `UPLOAD_DIR` | папка для загруженных работ (local-драйвер), по умолчанию `./storage/uploads` |
| `BLOB_READ_WRITE_TOKEN` | если задан — файлы хранятся в Vercel Blob и грузятся из браузера напрямую |
| `BLOB_ACCESS` | `private` (по умолчанию) или `public` — как создан Blob store |
| `APP_TIMEZONE` | часовой пояс колледжа для «сегодня», по умолчанию `Asia/Almaty` |

## Как устроен прогресс

Прогресс считается в одном месте — `src/lib/progress.ts` — и только из реальных действий:

- **лекция** — студент нажал «Я прочитал(а)» в конце лекции;
- **практика** — работа отправлена и не возвращена на доработку;
- **тест** — лучшая попытка ≥ проходного балла;
- **горячие клавиши** — на каждое сочетание темы хотя бы раз дан верный ответ в тренажёре.

Кнопка «Завершить тему» активна только когда все шаги выполнены, и сервер перепроверяет их перед тем, как засчитать тему. Если преподаватель возвращает работу на доработку, тема снова становится «в процессе».

## Хранилище файлов

Работы студентов сохраняются через интерфейс `StorageDriver` (`src/lib/storage`): локальный диск или Vercel Blob (включается переменной `BLOB_READ_WRITE_TOKEN`; браузер загружает файлы напрямую, минуя лимит Vercel 4.5 МБ на запрос). В БД хранится только `storageKey`, поэтому драйвер можно сменить без миграции. Файлы отдаются через `/api/files/[id]` с проверкой: владелец или преподаватель группы.
